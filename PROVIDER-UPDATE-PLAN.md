### New and verification rules

Keep the requested heading **New this week** with helper text **Recently added · shown for 14 days**.

- Draft assumption pending optional clarification: **verified** requires dated successful account access and usage evidence (or equivalent dated owner-provided usage confirmation). HTTP 200, public catalog, docs, owner placement, and logo matching alone do not qualify.
- API evidence records account access and a real successful request; installed-tool evidence records sign-in and a successful coding request. Scope/date appear in details. It does not certify ownership, model authenticity, continuous uptime, or every listed model.
- Verification for promotion expires **30 days** after the last successful evidence; a documented access failure, disable, or review status immediately revokes promotion. No account creation/tool execution occurs in this plan.
- New candidates must be active, verified, non-pinned, and have original `addedAt` age **0 ≤ age < 14 days**. Do not reset added date on return/edit/recheck/verification. ArtBloom Back is independent.
- Order by added timestamp descending; same-date ties by normalized name then stable ID; take first five. Use explicit ISO time zone; reevaluate on load, tab return, and next expiry boundary.
- Under this strict rule the current audit has **no qualifying usage-verified candidates**. Hide the strip until evidence exists. Empty-state wireframes are not verified provider claims. Referral and NEW do not certify free offers.

### Categories, search, and expansion

- Category tabs are a horizontal navigation of section anchors with active-section styling, not ARIA tab panels. On mobile support scrolling and accessible arrow controls.
- Each active section shows `min(6, N)`; if N exceeds six, **Show all (N)** expands in place and **Show less** restores the preview. N is matching canonical section total excluding pins; no pagination/page navigation.
- Needs review and Disabled start closed with total counts in disclosure headings. Opening shows up to six; Show all then applies. Helyx is sixth in the alphabetic Disabled archive. Reasons remain visible and disabled signup cannot activate.
- Search checks **all records**, including hidden tails and archives. Matching archive disclosures open temporarily; clearing search restores prior collapsed preference. Quick filters target active records by default; an explicit archive selection reveals matching archived records with disabled actions preserved.
- Search/filter views retain category grouping and fixed matching pins; suppress New/Spotlight while criteria are active to avoid duplicate results. Empty categories hide from current results/navigation. Result counts use unique IDs.
- Sort only non-pinned records **within** categories. Category order/pins stay fixed. Newest uses original addition date; updates have a separate label.
- Expansion persists for the page visit. Recalculate counts after criteria changes; preserve focus with the control or nearest visible heading if it disappears. Announce total matches via the existing live region.

### Weekly Spotlight

A single compact **Spotlight · Week of [date]** card appears after Recurring free offers. It promotes a verified lower-ranked entry without changing its canonical rank.

- Eligible pool: active, currently verified, non-pinned records **beyond the first six of their canonical category**. Exclude archives/review, unresolved access failures, pins, and current New entries.
- Weeks start **Monday 00:00 Asia/Manila**. Publish pool records with an explicit effective-week date and stable category-rank/ID order. The selected entry is `pool[(weekIndex - anchorWeekIndex) mod pool.length]`; no per-user randomness. New pool additions take effect next Monday. Immediately skip entries whose status/verification expires or whose ID is currently in New; scan forward once and hide the slot if none qualify.
- Compute week/selection in the static client from the dated published pool; no weekly automated deployment is required. Verification/status data changes still need normal review. Reevaluate at week boundary, verification-expiry boundary, and tab return. The next week's slot depends on published evidence, not click counts.
- One brief evidenced reason plus ordinary provider action; scope/date in details. No invented metrics or popularity claims. Empty pool hides the slot. Under strict evidence the current pool is empty; the mockup names no real Spotlight provider.
- Software similarity and click analytics never change eligibility rank or canonical order.

### Mobile and accessibility

- Full-width labeled search directly below the compact header; visible **No card**, **Install needed**, **Free credits** chips and More filters. All three are usable without the drawer; wrap at 320px instead of clipping labels.
- No card matches explicit documented no-card terms. Install needed matches primary-product installation, not optional API clients. Free credits matches an evidenced credit/trial allowance; recurring token offers remain in their categories. An owner badge alone, including Token Forge Starter credit, does not become verified free-credit metadata.
- Quick filters combine with AND; existing checkbox groups retain OR within each group. Show selected state, clear action, and result count. Preserve Ctrl/Cmd+K and drawer focus/inert behavior.
- On scroll, search/chips and category navigation stack with measured sticky offsets, safe areas, and section scroll margins. No large sticky hero. Large text can wrap; use non-sticky controls if their height obstructs content on short screens.
- Pins: four across on wide desktop, 2×2 intermediate, one column on narrow mobile. Category grids: 3/2/1 columns. Only New uses a horizontal strip; keyboard controls and no auto-carousel motion.
- Essential **Image Generation**, **Starter credit**, **Back**, **Referral**, **Unverified**, and **NEW** badges have reserved space outside the current four-generic-tag cap. Use text/color, current palette, visible focus, 44px touch targets, dark-theme contrast, and reduced motion.
- Compact cards prioritize logo/name, essential badge, actual offer/condition, availability, Details, and correct action. Move unknown metrics/technical detail into the modal. Action copy is **Get started / Install / View resource** as appropriate. Avoid implementation jargon in visitor flows.
